## Release 性能基准

每个基准独立运行五轮。FFT 每轮预热 3 次并计时 20 次；CSV 先预热 1 次再计时 5 次。完整解释见 [算法说明](algorithms.md)。

| 项目 | 五轮平均值 | 汇总 |
|---|---|---|
| 65,536 点 radix-2 FFT | 3.250、3.206、3.270、3.251、3.554 ms | 五轮中位 3.251 ms；全局最小单次 3.095 ms |
| 65,536 点 `computeSpectrum` | 5.908、6.034、5.992、6.447、6.453 ms | 五轮中位 6.034 ms；全局最小单次 5.544 ms |
| 10 MiB CSV 解析 | 161.136、161.629、159.020、163.666、157.247 ms | 五轮中位 161.136 ms；最小 152.417 ms；吞吐中位 62.059 MiB/s、峰值 65.610 MiB/s |

FFT 正确性同时得到主峰 `1000.011 Hz`（误差 `0.011 Hz`）、幅值 `1.018`（误差 `1.776%`）。CSV 文件实际为 10,485,764 字节、551,882 个样本；采样率、样本数与校验和均通过验证，临时文件在运行后清理。

相对阶段 3，同口径 FFT 和频谱中位数分别增加约 80.0% 与 23.3%。复核确认基准程序、CPU、GCC、Release 优化和 Performance 电源方案一致；生产 FFT/频谱在阶段 5 后新增分批 `std::stop_token` 检查，以满足协作取消响应门槛。该源码变化能解释两项同时上升，精度与取消测试均通过；[算法说明](algorithms.md) 保留了完整调查结论。Windows Defender 实时保护在本轮复核时处于启用状态，因此数字只作为当前机器基线，不作硬实时承诺。

## 稳定性、故障注入与发布包

- 30 分钟 Release Mixed 稳定性运行：通过。起止为 `2026-10-03T11:31:29.7625006Z`—`2026-10-03T12:01:35.0246793Z`，实际 1,805.262 秒；共 231 轮（46 轮全量、184 轮关键组、1 轮故障注入），累计 24,732 个测试实例，0 失败。原始证据位于 `cmake-build-release-mingw64/stage8-stability-final/`。
- 故障注入启动门禁：30/30 通过；其后稳定性循环不会静默重试失败轮次。
- Windows 目录包校验：通过。专用 Release 构建经 `windeployqt6` 和递归 MinGW DLL 闭包生成后，验证器确认 155 个文件、38 个 DLL、154 条包内哈希清单记录和 9 份白名单文档；所有 PE 均为 x64，非系统 DLL 依赖全部在包内闭合，活动数据库、导入存档、脚本输出和编译中间物未进入包。
- 同机隔离启动与解压复验：通过。验证器把包复制到 `%TEMP%` 独立目录，在只含 Windows 系统目录的 `PATH`、包内 Qt 插件和 offscreen 平台下运行 `SignalLab.exe --smoke-test`，进程正常退出；新建活动库 `integrity_check=ok`、无外键错误，迁移和内置演示信号正常。归档再解压到全新目录后，同一完整验证再次通过。
- 归档哈希边界：打包脚本只会在上述目录校验通过后发布 ZIP；最终 ZIP 的 SHA-256 仅记录在归档外部的同名 `.zip.sha256` sidecar，不写入其所在 ZIP 的内部文档。

- 在另一台干净 Windows 10/11 x64 机器或干净虚拟机上验证无需 IDE/Qt/MSYS2 即可运行。当前同机隔离 `PATH` 冒烟是必要证据，但不是这项验收的替代品。
