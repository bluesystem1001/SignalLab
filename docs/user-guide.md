# SignalLab 用户手册

## 1. 产品边界

SignalLab 是 Windows x64 上的一维离线信号分析程序，支持模拟信号、CSV/PCM16 WAV 导入、时域查看、双信号同轴对比、FIR、FFT/特征分析、后台任务、SQLite 追溯、SignalScript 和 PNG/数据导出。

当前版本不提供实时采集、多通道同步、网络协作、动态插件、机器学习或复杂报告。导入信号必须是非空、有限值、等间隔采样的一维序列。

## 2. 发布包内容与首次启动

把发布 ZIP 解压到源码仓库之外、当前用户可写的独立目录后直接运行 `SignalLab.exe`，不需要 CLion。不要直接运行源码树 `dist/` 下的暂存目录，不要放入只读目录或需要管理员权限写入的 `Program Files`，也不要只复制 exe；Qt/MinGW DLL、插件、迁移和数据目录必须保持原结构。

程序运行期间在自身目录按需创建或使用：

```text
data/signallab.sqlite3       项目数据库
data/imports/                按 SHA-256 保存的导入存档
data/script_outputs/         SignalScript 导出
```

当数据库在启动前不存在时，程序加入一个 48 kHz、0.02 秒、1 kHz 的内置正弦信号。若数据库已存在但为空，程序尊重用户的删除结果，不重新生成该信号。

如需没有演示信号的全新项目，先退出程序，再把 `data/templates/blank.sqlite3` 复制为 `data/signallab.sqlite3`。不要在程序运行时替换数据库。

## 3. 主窗口

左侧是项目内信号。选择一项后可查看名称、采样率、样本数和持续时间，并可执行分析、FIR 或删除。中央区域显示时域/频域图和分析结果；任务中心、分析历史和 SignalScript 位于相应页签。

状态不只用颜色表达：任务、错误和结果都有文字。耗时的文件读取、FIR、FFT/分析、脚本和数据库工作在后台执行，界面线程只负责交互和展示。

## 4. 导入 CSV

1. 单击“导入 CSV”并选择文件。
2. 在同一窗口选择逗号或制表符、是否有表头、从 1 开始的数值列。
3. 若文件有秒单位、严格递增且近似等间隔的时间列，选择该列以推导采样率；否则取消时间列并填写采样率。
4. 填写信号名称和单位，更新预览。
5. 只有当前参数对应的预览成功后才能确认导入；修改参数会使旧预览失效。

仓库样例 `data/samples/example_signal.csv` 使用逗号、表头、时间列 1、数值列 2，预览应为 21 个样本和 1000 Hz。

CSV 错误会报告从 1 开始的行列位置。空单元格、非法数字、NaN/无穷大、时间不递增或明显不等间隔都会被拒绝。

## 5. 导入 WAV

WAV 支持 PCM 格式 1、16-bit、单声道或双声道。双声道可选择左、右或平均；不支持压缩 WAV、浮点 WAV、24/32-bit 或超过两声道。

`data/samples/example_signal_pcm16.wav` 是可直接导入的 1 kHz、单声道、21 帧固定样例。格式损坏或截断时，错误信息包含文件和字节偏移。

## 6. 文件去重与项目存档

原文件按 SHA-256 存到 `data/imports/<hash>.source`。同一文件内容只保存一份，但不同解析选项可形成不同逻辑信号；只有“文件内容 + 解析选项”都相同才算重复导入。

外部原文件不会因项目删除而被修改。多个逻辑信号共享同一项目存档时，只有最后一个引用删除后才清理存档。

## 7. 波形、对比与时间轴

主信号用实线显示，可从“对比信号”选择第二条虚线。两条信号：

- 各自以第一个样本为相对 `t=0`；
- 共用以秒为单位的 X 轴，不做重采样、插值或自动相位对齐；
- 完整时间域取两者较长持续时间；短信号结束后不伪造末值；
- 单位不同时，Y 轴标题同时标明两种单位；
- 各自按当前可见区降采样，保留桶内极值。

滚轮、矩形框和“横向放大/缩小”只改变时域 X 轴，Y 轴保持稳定。完整视图时图下时间轴滑动条禁用；放大后可拖动它在完整时间域内平移固定宽度的窗口。松开滑块会立即绘制最终位置，“复位”恢复完整时间域并禁用滑动条。

十字光标分别显示两条信号最近样本；若光标超过短信号范围会明确显示“超出范围”。按住 Shift 选择区间会分别报告两条信号的样本数。切换主/对比信号或复位会清除旧选区。

## 8. 分析

“后台分析所选信号”依次计算基本特征、去直流、Hann 窗、自动补零、自研 radix-2 FFT、单边谱、峰值、SNR 和 THD。

默认结果包括均值、总体方差、RMS、峰峰值、主频、主峰幅值、SNR、THD 和 FFT 点数。没有可用主峰或指标定义不适用时显示“不可计算”，不是程序错误。

分析成功后才以一个事务写入特征和 SUCCEEDED 状态。分析历史保存信号名、状态、算法版本、规范化参数 JSON、输入/输出哈希和 UTC 时间，重启后仍可查询。

## 9. FIR 派生信号

FIR 侧栏支持低通和高通。截止频率必须满足 `0 < cutoff < sample_rate/2`，抽头数必须是至少 3 的奇数。当前使用 Hamming 窗设计、零填充边界、因果卷积，输出与输入等长且不补偿群延迟。

任务成功后生成并选中一个持久化派生信号，来源和参数可追溯；相同输入和参数采用稳定来源键，不重复创建数据库记录。

## 10. 任务中心、取消和重试

任务状态为排队、运行、成功、失败或取消，进度不会倒退。排队任务可取消；运行中的长循环协作检查取消。任务若已经越过成功提交边界，迟到的取消不会把成功改成取消。

终态任务可以重试，新任务会记录来源编号。终态快照也可从本次任务中心移除，但这不会删除分析历史、脚本历史、信号或文件。信号删除任务不能在任务中心直接重试，必须回项目列表重新确认影响范围。

## 11. 删除

删除操作都有边界明确的确认框，默认焦点为“否”。

- **分析历史**：只能删除终态记录；同时删除其特征结果，跨重启生效，不删除信号。
- **任务中心**：只移除本次进程内的终态快照，不删除持久化历史或文件。
- **项目信号**：删除数据库中的信号/来源，保留既有分析历史、任务快照、脚本历史和 FIR 派生信号；分析记录的信号外键会置空。有关联分析或 FIR 正在排队/运行时禁止删除。

删除信号的数据库提交是逻辑边界。提交后若物理存档清理失败，界面显示警告，但不会把已经提交的删除伪装成失败。删空项目后详情、图表和分析结果清空，重启也不会重建内置信号。

## 12. SignalScript

SignalScript 支持 `load`、赋值、函数调用、`|>` 管道、`plot`、`save`，以及 `normalize`、`lowpass`、`fft`、`features`。编辑器显示诊断、变量、输出、AST 和结构化信号/频谱；诊断可点击跳转，执行历史可重新载入源码。

现场可重复演示使用 `data/samples/demo_analysis.sig`。`example_analysis.sig` 还展示 `save`，会在 `data/script_outputs/` 创建文件，但出于安全不会覆盖同名输出。

脚本只能访问宿主配置根内的相对路径；绝对路径、`..`、符号链接/junction 逃逸都会拒绝。解释器没有 Shell、子进程、网络或动态加载能力。完整语言规则见 `docs/signalscript.md`。

## 13. 图表与数据导出

图表可导出 PNG；写入失败时界面会给出原因和重试建议。SignalScript 的 `save` 可导出信号/频谱 CSV 或特征 JSON；非有限可选指标在 JSON 中写成合法 `null`。

导出前确认当前图表和信号选择正确，尤其是在双信号对比模式中。PNG 是展示结果，不替代数据库中的可追溯分析记录。

## 14. 备份、迁移与恢复

正常退出程序后再备份：

- `data/signallab.sqlite3`；
- `data/imports/`；
- 需要保留的 `data/script_outputs/`。

数据库与 imports 应成组备份，否则恢复后可能出现缺失存档。不要只复制 `-wal`/`-shm` 文件，也不要在程序运行时手工编辑 SQLite。

若数据库无法打开，先复制整个 data 目录留证，再检查错误和 `PRAGMA integrity_check`。不要删除损坏文件后声称数据已经恢复。确需从空项目开始时，保留旧目录并使用固定空白模板。

## 15. 常见问题

### 程序提示缺少 DLL 或 platform plugin

发布包不完整，或被从原目录单独复制了 exe。重新解压完整包，确认 `platforms/qwindows.dll` 和所需 Qt/MinGW DLL 在包中。不要把开发机其他 MinGW 加到系统 PATH 作为永久修补。

### 提示 QSQLITE 不可用

确认 `sqldrivers/qsqlite.dll` 以及它的 SQLite/Qt 依赖都在包中。不要把另一个 Qt 版本的插件混入目录。

### 重复导入没有新增信号

完全相同的文件内容和解析选项会被识别为同一逻辑信号。要导入另一个列或采样率，修改对应选项并重新预览；不要修改文件只为绕过提示。

### 取消后任务仍成功

小任务可能在点击前已经完成提交。取消只对尚未越过成功提交边界的工作生效；这是为了避免数据库已成功但界面显示取消的矛盾。

### 脚本第二次 save 失败

输出安全策略不覆盖已有文件。使用不带 save 的演示脚本，或在确认不再需要后把旧输出移到备份目录，再重新运行。

### 滑动条不可用

完整时间域无需平移，所以滑动条禁用。先横向放大；复位后它会再次禁用。
